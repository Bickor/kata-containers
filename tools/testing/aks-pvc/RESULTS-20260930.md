## Issues encountered / boundaries

1. First guest-mount attempt hit missing staging `mountInfo.json` because node
   recognition occurred after stage. Removing both test claim consumers, waiting
   for unstage, then recreating them fixed it. This driver initialization behavior
   is a remaining integration issue, not fixed by the runtime PR.
2. Running many Kata consumers/replacements filled the 148Gi node OS disk with
   EROFS snapshot data and caused transient failures, including a raw-disk lock
   failure. Removing extra test pods freed storage. SMB replacement and raw-block
   replacement were then independently rerun successfully. The helper now reduces
   simultaneous Kata consumers.
3. Ordinary filesystem PVCs are not fixed by this port. The dedicated StorageClass
   is necessary for the tested SMB path.
4. The hosted demo API still needs tenant-aware volume support. This test used
   direct Kubernetes pods, not the hosted API.
5. Not tested: NFS, cross-node failover, CSI expansion, VM snapshot/restore with
   mounted PVCs, guest-managed Azure Disk filesystems, or confidential-policy mode.
